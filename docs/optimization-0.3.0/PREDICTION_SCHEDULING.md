# 精细预测的生成顺序

0.0.3 只阻止粗预测进入渲染器。原 VSS 调度仍先铺满中景父层，再让附近的叶子精修；被画质筛选隐藏的父层因而消耗了第一批生成预算。

现有 RTF 自定义山地测试的实际记录中，7 个已生成瓦片全部是隐藏粗网格，合格瓦片和 GPU 上传均为 0，仍有 228 个中景覆盖目标。采样累计 126.9 秒，其中着色累计 83.3 秒；CPU 预算拒绝计数 1485。这些数字表明调度和采样成本同时存在，不能把所有等待时间归因于一个开关。

实际 `PredictionTileManager` 私有方法的隔离反馈测试也复现了依赖：同一近处完整网格目标在父节点未完成时，`terrainParentReady=false`、`mediumWorkAllowed=false`，优先级为 100006，而隐藏根节点为 10000。

## 改动范围

`PredictionQualityWorkMixin` 仅在“LOD 画质优先”和“优先完成近处精细预测”同时打开时生效。

- 仅处理原规划器已选择、目标为完整 64 格、最终采样间距为 1–2 方块的叶子，不扩大精细预测范围。
- 这些叶子可以跳过隐藏父层和中景覆盖的先决条件。
- 仍按原有 16 → 32 → 64 网格逐步生成；中间结果继续受到画质筛选，不作为粗模显示。
- 在同一距离带内，优先完成已经开始的网格；保留视角前后台判定和后台优先级偏移。存在望远镜焦点时不重写任务优先级，但选中精细叶子的父层依赖仍可解除。
- 把这些任务计入普通精修，保留原有精修线程、帧预算、CPU 许可、内存预留和重试限制。
- 关闭独立调度开关后恢复 VSS 顺序，画质筛选保持开启。

没有修改采样、着色、网格构建或缓存内容格式。不会以降低地形精度换取更快的计数结果。

近处完整网格的优先级高于隐藏父层，因此静止场景会先完成有限的近处任务；持续移动、不断产生新近处任务时，远处覆盖与后台任务可能长期延后。此策略没有为所有距离提供最迟完成时限，用户可以独立关闭它。它也不能越过原有 CPU、帧时间或内存限制来保证固定的生成速度。

## 验证接口

`tests/client/PredictionPriorityProbe.java` 调用实际 manager 的入队判定和优先级方法，检查独立关闭、未选中瓦片、就近完成，并将无父节点的完整叶子交给实际驻留快照类和渲染覆盖选择，要求 4096/4096 格可选中。这是驻留与覆盖逻辑验证，不自行上传真实 GPU 网格，也不启动生成工作线程。

`tests/client/PredictionProgressProbe.java` 在 RTF 山地 `(3080, -4088)` 固定视角观察 60–180 秒，记录首次合格网格和首次实际绘制的观察时间。正式候选验证要求完整 180 秒窗口。第 2 版探针在窗口开始记录渲染器累计计数，随后要求合格快照非空，而且窗口内 GPU 上传与渲染计数均增长；启动阶段较早发生的绘制和“粗网格成功隐藏”都不能单独通过。它同时记录每秒采样的堆占用峰值和 `RenderFrameEvent.Post` 帧间隔分位数，不修改生成线程数、限帧或预算。

结果由 `tools/prediction_progress_report.py` 核验。先保留旧版冷缓存数据，再用相同世界、位置、窗口和配置测试候选 JAR。原始实测输出保留在构建目录；此说明本身不代替通过记录，也不证明所有电脑都能达到相同生成时间。

报告区分第 2 版窗口增量证据和旧累计计数证据。旧记录只可作为零输出参考；完整比较要求基线也使用第 2 版探针，并核对实际最大堆、生成并发、预测距离、场景和 NeoForge 版本。`--benchmark` 可在校验通过后生成 `BENCHMARK.md`；外形诊断模式的不同计时范围禁止用于正式性能结果。
