# 客户端下载反压与预测内存恢复

## 下载跟随本地处理速度

钠面板中的“下载跟随本地处理速度”对应 `clientIngestBackpressure`，默认开启，可热切换。

接收服务器 LOD 的速度会同时参考等待解码的列数、压缩数据字节数，以及 Voxy 尚未处理的真实区段数。达到高水位时暂停新的扫描请求；积压继续增加时，完整下载列保留在有界压缩队列中，暂缓解码。降到低水位后自动继续，不清空已经收到的列。

停止与恢复门槛按有效 Voxy service 工作线程数调整，使用不同水位避免频繁开关。这个门槛是积压控制，不是总内存配额；原版区块摄入和正在处理的一个完整列仍可以暂时超过停止线。

已完整收到的列等待本地处理时，维护其原 requestId 的有效期，避免“本地忙碌被当成服务器超时→重复下载→旧列作废”。每个仍匹配的请求最多每秒刷新一次；没有响应或还没收齐分片的请求继续使用原超时机制。完整列并不会提前获得成功确认，仍需通过原会话、内容版本校验和摄入回调。

切服、清理待收数据和断开连接会重置队列租期与反压状态。关闭此开关恢复原下载/解码节奏；服务端时间窗、全局限速和每玩家限速继续生效。

切服交接还需要防止旧解码任务取走新会话的列。现在用短队列锁，将会话 epoch 校验、出队以及列数/字节计数修改与清理操作原子化；等待下游和解码不占用这把锁。旧任务结束时只释放自己会话的处理标记，旧 `finally` 不能清掉新会话的 `processing`，也不能放行重复的解码任务。

## 精细预测的内存恢复

本修复随“LOD 画质优先”和“优先完成近处精细预测”两个现有开关同时启用，不增加更粗的显示模式。

精细叶子可以独立于隐藏父层生成，因此旧的“必须有父层才能回收子层”规则可能在内存不足时形成等待：旧细缓存不能释放，父层又拿不到生成空间。

现在只在原有内存压力回收路径中额外允许清理满足全部条件的预测缓存：

- 位于细网格层 LOD 0 或 1，包括完成的 64×64 网格，以及移动后留下、被画质筛选隐藏的 16/32 格中间缓存。
- 当前规划已经不需要，且没有正在构建的任务。
- 已超过用户预测视距再加 1024 方块的退休边距。
- 原有望远镜、当前使用及其他回收保护仍允许释放。

释放沿用 VSS 原 `removeTile` 路径，回收内存许可和表面状态，更新渲染所有权；下一次驻留同步移除对应 GPU 引用。**不删除预测磁盘缓存，不删除真实 Voxy LOD 存档，不降低仍在视距内的精细地形质量。**没有可安全释放的远处缓存时继续等待可用内存，不扩大内存预算，不拿粗模填充。

## 验证范围

- `tools/ingest_backpressure_test.py --sources`：真实处理器在 Voxy 积压时保留两条队列与字节，恢复后按原次序处理；关闭和会话重置有效。
- `tools/ingest_timeout_test.py`：真实请求追踪与 manager 验证完整列长暂停后仍能一次摄入，未回复请求正常超时，新的完整列不会被刷新节流遗漏，超时堆保持有界。
- `tools/ingest_session_test.py`：先将真实处理器的旧任务阻塞在反压检查，再切服并放入新列，最后恢复旧任务。旧产物出现“0 列、0 字节、未摄入”；重建产物在同维度重连和跨维度切换中均保留 1 列及全部 44 字节，旧 `finally` 保留新会话的处理标记，当前任务随后恰好交付一次。测试只替代世界输入和网络出口，不替代实际处理器、队列、分片组装与解码。
- `tools/prediction_pressure_test.py`：真实 adaptive 内存预算和 manager 的无游戏合同；`--baseline` 保留旧行为的失败反馈，无参精确重定向与生产相同的两个回收调用，检查远处释放、近处保留和重新调度。
- `tests/client/PredictionPressureProbe.java`：由原生测试启动器加载同一合同，额外验证实际 Mixin 接线。该结果单独记录，不能用无游戏合同代替。

这些测试验证恢复与数据交接，不承诺任意硬件的固定帧率，也不等于所有存档已通过完整视觉回归。
